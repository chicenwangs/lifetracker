# fix #434 — Search's empty results are not a listbox any more

- What changed for the user: nothing visible. Screen readers no longer get a `role=listbox` around the "What you open from here shows up first next time." / "Nothing found" hint (a listbox may only contain options, axe `aria-required-children`). With results the listbox and its options are exactly as before.
- Implementation: the results container keeps `id="cmdk-list"` and the hint child, but `role="listbox"` and `aria-label="Results"` are only rendered when there are results. The combobox's `aria-controls` / `aria-activedescendant` wiring is unchanged.
- Files: `app/src/lib/components/CommandPalette.svelte`, `app/tests/e2e/phone/search.spec.ts` (axe on empty + results), `app/tests/e2e/flow.spec.ts` (same on desktop).
- Tests: phone `search.spec.ts` phone + phone-landscape 6 passed; desktop `flow.spec.ts` 48 passed (new test included); lint, svelte-check, unit.
- Doc lines to change: none.
