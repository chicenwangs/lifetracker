# PR 14 — type starter pack

- User: **Settings › Types** has **+ Add a preset ▾** under the list: Class · Errand · Health · Chore · Study, each
  with its colour dot. One tap adds the type (the existing type bar and quick add pick it up at once). Class arrives
  with **Month calendar off** (a timetable should not flood the Month grid). A preset whose name already exists is
  greyed **"(have it)"**; if another type already owns the preset's quick-add word the add is skipped with a note
  ("Skipped Class: /class is already the quick-add word of …"). At the 10-type cap the button is replaced by
  "All 10 type slots are used. Remove a type to add more." Every added type shows a toast with **Undo**.
- Server: `item_types.createSchema` takes `onCalendar` (default true, so Class can be created off the Month grid);
  `POST /api/item-types` now journals one undo entry (`Add type "<name>"`) and returns `{ type, undo }`. Built-in
  types stay undeletable (existing repo check); the cap stays 10.
- Client: `TYPE_PRESETS` + pure `presetState()` (`$lib/itemtypes.ts`: add / have / clash), the preset `<details>`
  menu and handlers in `routes/settings/types/+page.svelte` (48 dp rows on phone).
- Files: `app/src/lib/itemtypes.ts`, `app/src/lib/server/repo/itemtypes.ts`,
  `app/src/routes/api/item-types/+server.ts`, `app/src/routes/settings/types/+page.svelte`,
  `app/tests/unit/itemtypes.test.ts`, `app/tests/e2e/type-presets.spec.ts`,
  `app/tests/e2e/phone/type-presets.spec.ts`.

  (34.2s) · lint + check clean.
