# fix #414 (attempt 2) — the #378 test: a reminder snackbar ate the Save tap

- Root cause, proven locally with a real due reminder: after `page.goto('/today')` the reminder inbox check runs **asynchronously** (`inbox.ts` `watchInbox` → `check()` on mount). The test's "no toast" wait can pass before that fetch resolves, then a 15 s reminder snackbar appears over the open Add sheet. The Save button's centre (landscape: 710,310) sits inside the snackbar band (bottom 76 px + 48 px), so the CDP touch hit the snackbar's **"Snooze 10 min"** button: no `POST /api/keep/notes`, the sheet stayed open, `.tap-guard` never mounted, `guardSeen` timed out. That is exactly the CI failure (fresh DB per run; any due reminder from an earlier spec can do it — portrait passed, landscape failed 3 min later).
- Fix (test only, no app change, no weakened assertion): before the burst, the test closes any visible snackbar (`button[aria-label="Close"]` in `.toast`) and waits until `document.elementFromPoint` at the Save spot really is the Save button. Then the original burst + guard assertions run unchanged.
- Evidence: temporary probe (deleted, never committed) with a real due reminder: before the fix `atPoint` was the toast's "Snooze 10 min", `net: []`, sheet open, no guard; with the fix the toast is cleared, `toastSeen=true`, the guard mounts. Logs in the session; not committed.
