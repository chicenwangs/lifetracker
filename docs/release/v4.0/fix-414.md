# Fix #414 — flaky #378 rapid-taps test

- **User:** no app change. The phone test "rapid taps after Save note do not reach the page beneath (#378)" is now deterministic on slow CI runners.
- **Cause:** `.tap-guard` exists for 400 ms after the keep-note reply; the test polled for it with the 5 s expect default, so a slow reply (or a stall between polls) made it miss the window.
- **Files:** `app/tests/e2e/phone/plus.spec.ts` — arms a MutationObserver before the Save tap, records the guard's mount and that it covered the Save point, waits for that flag (15 s) instead of polling the transient; the burst taps and outcome assertions are unchanged.
- **Tests:** `--repeat-each 10 --project=phone-landscape` 90 passed · `--project=phone` 90 passed · a 6 s delayed keep-note reply passes the new wait (the old 5 s expect would fail). CI run IDs that showed the flake: 45629031169, 45630281287, 45635323727.
- **Docs to change:** none.
