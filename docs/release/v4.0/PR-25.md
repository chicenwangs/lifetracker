# PR 25 — DB gallery view

- A database can have a Gallery view: `+ View` → Gallery. Cards: 16:9 cover, title, up to 2 property chips (`Card shows`, the same picker as the board; gallery + board share it).
- Cover chain (DESIGN 2.7, final): an uploaded file in the `Cover` url property (`/api/attachments/att_<16>`) → the record page's cover (`pages.cover_attachment_id` from migration 0012 / PR 31; `databases.get` LEFT JOINs pages and `DbRow` carries `coverId`) → the record page icon (`DbRow.icon`) on `--ground` → plain `--ground`.
  - CSP is `img-src 'self' data:` (no outbound image fetches). An external https picture link cannot render, so it is a valid url value for a link cell but is ignored for the cover; the e2e proves the uploaded path decodes (naturalWidth > 0, no CSP console error) and that an external link falls back to the page icon.
  - The DB has no separate image property type: DESIGN's "image property" is a `url` property.
- View settings: `Cover` (url properties), `Card size` S / M / L = 180 / 240 / 320 px, `Card shows`; on the phone they open in the shared BottomSheet. Click a card opens the record (creates its page first). Empty gallery = "No records yet." + `New record`. Phone: 2 columns for S/M, 1 for L; cards ≥ 48 dp.
- `checkValue('url')` accepts a same-origin `/api/attachments/att_<16>` path as well as http(s)/mailto (uploaded files under the strict CSP); its error message names the uploaded form.
- Config/plumbing: `ViewConfig` gains `coverProp` (must be a url property, checked in `checkConfig`) and `cardSize`; the views route accepts `gallery`; `cloneSchema` remaps `coverProp` and keeps `cardSize`. Merged with PR 24 (calendar): the same DB can hold table/board/calendar/gallery views and the config carries `groupBy`/`cardProps`/`coverProp`/`cardSize`/`dateProp` together.
