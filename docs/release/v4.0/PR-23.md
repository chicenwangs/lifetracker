# PR 23 — DB board view

- A database can now have a Board view: `+ View` opens a type picker (Table / Board) and asks for a name, then the view switches to it. View tabs show the type glyph.
- Board = one 260 px column per select option, in option order, plus a final `No value` column; each header shows the option colour dot, name and card count, with `+ New` at the bottom. Cards show the title and up to two chosen properties.
- `View settings` (board only): `Group by` (the select properties) and `Card shows` (two property pickers). Saved in the view's `config_json` (`groupBy`, `cardProps`).
- Move a card: desktop drag onto a column, or the card `⋯` menu `Move to <column>` (buttons, so the keyboard path is Tab + Enter); phone shows one column at a time with a columns chips row, long press lifts a card and the next chip tap drops it, and the `⋯` menu works too. Every move shows `Moved to <column> · Undo`, which puts the old value back.
- No select property: "Board groups cards by a select property." + `Add a select property` (opens the add-property panel). Calendar / Gallery stay for PRs 24–25; the type picker is where they will be added.
- Also fixed in this PR: a real pointer click on a database button/tab inside the page editor could be swallowed (the editor re-rendered the block between mousedown and mouseup, seen as the Board tab not switching in phone landscape). The block now prevents the editor's mousedown default on phone for buttons and cards.
