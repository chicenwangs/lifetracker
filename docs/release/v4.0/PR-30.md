# PR 30 - reminders on page to-dos

- **User:** put the cursor in a to-do -> **Remind me** (desktop block tools; phone block sheet) opens the existing reminder picker. Exact times only (a to-do has no date). A bell chip after the text shows the due time; the chip reopens the picker. Ticking the to-do cancels the reminder: the chip stays visible, struck through and disabled (DESIGN 2.9), with a "Reminder cancelled - Undo" toast; Undo un-ticks and the next save brings the reminder back. Deleting the to-do cancels its reminder on the next save.
- **Storage:** `reminders.source_type = 'page_todo'`, `source_id = pageId:blockId`. Migration 0012 already allows the type; no new migration. The block id is a new `taskItem.blockId` attr (`pbl_` + 16), kept in the saved doc by the extended `TodoItem`; page saves rebuild `page_blocks` rows, so this is what makes a reminder survive.
- **Access:** adding needs `need('page', user, pageId, 'edit')` - owner or editor; viewers and strangers get 404/403. Reminders stay private to whoever set them: `list` and `forPage` are owner-scoped, and the duplicate-time guard is per owner, so the page owner and an editor may both set a reminder at the same instant without seeing each other. `sourceInfo` requires `level('page')` (a revoked share or trashed page cancels on the tick). `/api/native` alarms include them, and `notify_pages` is respected like every pages reminder.
- **Chips:** `GET /api/reminders?page=` returns this user's `scheduled` reminders plus `cancelled` ones whose to-do is ticked, so a done to-do keeps its struck chip; a cancelled reminder on an unchecked or deleted block is not returned. The chip is a ProseMirror decoration (no reminder state in the saved doc) and is disabled while the to-do is ticked.
