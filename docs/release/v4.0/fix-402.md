# fix #402 — the offline queue retries by itself

- A queued note or planner change is now retried every 30 s while the queue still holds something, so it syncs when only the server comes back (browser never fires `online`). It stops as soon as both queues are empty, and a retry never starts a second flush: it reuses the run already in flight.
- Sign-out still wipes the queue and cancels the retry.
- Files: `app/src/lib/client/offline.ts`, `app/tests/unit/offline.test.ts`.
- Tests: lint, svelte-check, unit 427 (new: retry after a 500, one queue's retry survives the other queue emptying, single flush in flight; the retry tests fail without the change); desktop `flow.spec.ts` (including the offline queue test); phone `offline.spec.ts`, `keepretry.spec.ts`, `keep.spec.ts` on phone + landscape.
- Doc lines to change: `docs/adr/009-offline-sync.md` line 11 ("sent in order when back online") — add that it also retries every 30 s while ops wait, so a server that returns without an `online` event still syncs.
