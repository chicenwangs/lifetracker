# QA #398 - Today listed a repeating entry twice

- **Cause:** an item created with `/both` has a planner block linked by `blocks.item_id`. On a repeating item the day list shows the occurrence (`id = item@date`, `seriesId = item`), while the block's `item_id` is the base id, so the linked block was never matched and both rows were drawn.
- **Fix:** Today hides a block whose item occurrence is already listed for that day. The match uses `seriesId ?? id`; blocks linked to all-day items, items on another day or deleted items stay. The item row keeps the repeat's **Skip this one** action (owner decision a).
- **Files:** `app/src/lib/day-rows.ts` (pure `withoutLinkedBlocks`) · `app/src/routes/today/+page.svelte` (one filtered item list feeds both the block filter and the item rows).
- **Tests:** unit `tests/unit/day-rows.test.ts` - 3 passed (plain linked, repeat occurrence via seriesId, other-day/all-day/unlisted kept). E2E `tests/e2e/today-repeat-dup.spec.ts` creates `Repeat dup today 9am to 10am /both every day` through quick add, expects one row and the Skip this one action.
