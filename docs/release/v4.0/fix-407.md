# fix #407 — desktop action sheets behave like dialogs

- Escape now closes a desktop action sheet (Postpone, Slipped/row ⋯, block actions) and focus goes back to the button that opened it. Tab stays inside the sheet instead of reaching the page behind it.
- Escape in an open `/` list or a title/notes field closes that first; the sheet stays.
- Phone unchanged: Back still closes only the top layer, and the sheet keeps its own gesture/Close paths.
- Files: `app/src/lib/components/BottomSheet.svelte` (one `use:modal` action), `app/src/lib/client/modal.ts` (keydown listener capture → bubble, so an inner field/menu consumes Escape first), `app/src/lib/components/CommandInput.svelte` (stop propagation only while the `/` list is open), `app/tests/e2e/slipped.spec.ts` (new desktop test).
- Tests: lint, svelte-check, unit; desktop `slipped.spec.ts`; phone sheet/back/keepnote/reschedule/keep/smoke specs.
- Doc lines to change: none (behaviour now matches the existing `modal.ts` contract).
